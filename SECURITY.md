# Security Policy

This is the primary security document. For Simplified Chinese, see the: **[中文安全政策](SECURITY.zh-cn.md)**.

For general information about the extension, see the [README](README.md).

## Supported versions

Security fixes are applied to the latest release only; older releases are not patched.

Each version bundles a native engine binary, so **always use the latest version**. Security updates are normally released together with regular feature updates.

## Reporting a vulnerability

**Do not report security vulnerabilities through public issues.**

Report them privately through either channel:

- GitHub private vulnerability reporting: [https://github.com/XKPU/sqlite-libsql-preview-edit/security/advisories/new](https://github.com/XKPU/sqlite-libsql-preview-edit/security/advisories/new)
- Email: `csaxongmail@gmail.com` or `u-eptm@u-eptm.top`

### Please include

1. **The affected version**, plus your OS and architecture.
2. **A description** of the issue and its impact (for example: arbitrary code execution, unauthorised file read).
3. **Steps to reproduce**, preferably with a minimal database file.
4. **A suggested fix**, if you have one.

### What to expect

- **Acknowledgement** — usually within 7 days.
- **Assessment and fix** — once confirmed, a fix is prepared while the report stays private.
- **Public disclosure** — published as a GitHub security advisory once the fix is released, crediting the reporter unless you prefer to remain anonymous.

Please do not disclose the issue publicly before a fix is released.
